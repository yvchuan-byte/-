# v3.0 数据库设计

沿用用户、设备、指标、遥测事件和接入异常表，并在启动时为旧设备/事件表安全补充在线状态及质量字段。

## metric_aggregate_1m

以 `bucket_start + device_code + metric_code` 为主键，保存分钟均值、最小值、最大值、样本数、异常样本数和更新时间。迟到超过 60 秒的事件标记异常。

## alert_rule

保存规则名称、可选设备范围、指标、操作符、阈值/区间、连续次数、严重级别、冷却时间和启用状态。

支持操作符：`GT`、`GE`、`LT`、`LE`、`BETWEEN`。

## rule_state

以规则和设备为主键保存当前连续命中次数及最近告警时间，用于跨事件计算连续次数和冷却。

## alert_record

保存触发规则、设备、指标、触发值、严重级别、状态、触发/确认/解除时间和说明。状态为 `OPEN`、`ACKED` 或 `RESOLVED`。

## 设备和遥测扩展

- `device.status`：`ONLINE` / `OFFLINE`。
- `device.last_seen_at`：最近一次有效事件接收时间。
- `telemetry_event.quality_status`：`0` 表示正常，`2` 表示迟到异常。
- `ingest_error`：沿用 v2 的错误隔离表，记录原始数据、检测原因及时间。
