# 智慧园区能耗与环境监测系统 v2.0 需求规格说明书

## 1. 版本与迭代范围

- 版本：v2.0（Sprint 2：数据接入）。
- 目标：在 v1.0 的登录、角色、设备档案和指标目录基础上，实现本地遥测模拟、JSON/JSONL 接入、数据校验、异常隔离和 SQLite 持久化。
- 本版不实现实时聚合、阈值告警、历史查询、CSV 导出、审计和用户管理。

## 2. 用户与权限

沿用 v1.0 的管理员、运维人员和只读用户。设备写操作仅管理员和运维人员可用；只读用户可以查看已接收数据，但不能启动模拟器或导入数据。

## 3. 功能需求

### FR-01 登录及基础档案

沿用 v1.0 的演示用户、设备档案和指标目录。启动时创建或读取本地 SQLite 数据库。

### FR-02 本地模拟器

管理员和运维人员可启动/停止模拟器并设置 1–60 秒采集间隔。模拟器针对已启用设备及其适用指标生成带唯一 eventId 的遥测事件，事件进入处理队列，由桌面主线程依次验证并入库。

### FR-03 JSON/JSONL 文件接入

支持单个 JSON 事件、JSON 事件数组，以及逐行 JSON（.jsonl/.ndjson）文件。文件中的单条解析或校验失败不得中止其他记录的处理。

### FR-04 数据校验与去重

校验事件必需字段和类型、UUID eventId、设备编号、事件时间及时区、有限数值、启用设备/指标、指标单位和指标范围。无效记录写入 ingest_error；相同 eventId 不重复入库。

### FR-05 遥测存储与展示

有效事件写入 telemetry_event，保留原始 JSON、事件时间及本地接收时间。数据接入页显示最近接收的事件和每批导入/处理结果。

## 4. 非功能需求

- 桌面界面沿用 Python 标准库 Tkinter，不依赖第三方 UI 库或外部网络。
- 模拟器生产线程只负责生成事件并写入线程安全队列；SQLite 写入在 UI 主线程完成。
- 单条坏数据不得阻断队列中后续事件。
- 数据保存在应用目录的 SQLite 数据库中。

## 5. 验收标准

1. v1.0 的三种演示账号、设备档案和指标目录仍可用。
2. 可启动、停止模拟器；生成的有效事件可在界面和数据库中查看。
3. 有效 JSON/JSONL 记录可入库，重复 eventId 被忽略。
4. 缺字段、错误类型、非法 JSON、未知设备/指标、单位不符和超范围数值被隔离并记入 ingest_error。
5. 一个输入文件中的无效记录不会阻止后续有效记录入库。
6. 项目可通过 `python -m unittest discover -s tests -v` 测试，运行不要求第三方 UI 依赖。
