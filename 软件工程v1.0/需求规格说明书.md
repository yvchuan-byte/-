# 智慧园区能耗与环境监测系统 v1.0 需求规格说明书

## 1. 版本与迭代范围

- 版本：v1.0（Sprint 1：需求与基础框架）
- 目标：明确第一代系统需求，建立桌面程序骨架、本地 SQLite 数据库、登录角色、设备档案和指标目录。
- 本版不包含数据模拟/接入处理、实时计算、告警、历史查询、CSV 导出、审计页面和用户管理页面；这些属于后续迭代。

## 2. 系统用户与权限

| 角色 | 本版权限 |
|---|---|
| 系统管理员（ADMIN） | 查看设备与指标；新增、编辑、启用/停用设备 |
| 运维人员（OPERATOR） | 查看设备与指标；新增、编辑、启用/停用设备 |
| 只读用户（VIEWER） | 登录并查看设备与指标，不允许修改设备 |

首启演示账号：`admin / admin123`、`operator / operator123`、`viewer / viewer123`。密码以 PBKDF2-HMAC-SHA256 哈希形式保存在本地数据库中。

## 3. 功能需求

### FR-01 登录

用户使用用户名和密码登录。凭证无效或用户停用时，系统拒绝登录并显示错误信息。成功登录后显示用户名称和角色。

### FR-02 设备档案

系统显示设备编号、设备名称、设备类型、所属区域、安装位置和启用状态。管理员及运维人员可新增、编辑设备档案和启用/停用设备；设备编号由英文字母、数字、下划线和连字符组成，且不可为空或重复。只读用户不可执行写操作。

### FR-03 指标目录

系统显示指标编码、指标名称、单位、取值范围和启用状态。v1.0 提供有功功率、温度、湿度和 PM2.5 四项基础指标。

### FR-04 遥测交换格式

系统定义可供后续迭代使用的遥测 JSON 格式，包括事件 ID、设备编号、指标编码、数值、单位和 ISO 8601 事件时间。格式定义见 [`telemetry_event.schema.json`](./telemetry_event.schema.json)。v1.0 仅定义格式，不接收或处理遥测消息。

### FR-05 本地数据存储

SQLite 数据库存储用户、设备、指标及预留的遥测事件表。程序首启时创建数据库结构并初始化演示用户、设备和指标。

## 4. 非功能需求

- 桌面运行：系统在独立桌面窗口中显示，不主动启动外部浏览器。
- 本地化：SQLite 数据保存在程序目录；桌面主界面不需要网络连接。
- 界面：使用 Python 标准库 Tkinter，不依赖第三方 UI 库。
- 权限：只读用户不提供设备新增、编辑和启停操作入口。
- 易用性：设备和指标使用表格呈现，设备新增/编辑使用表单。

## 5. 验收标准

1. 三种演示账号均能登录，角色名称正确显示；错误密码不能进入系统。
2. 只读用户可浏览设备和指标，尝试调用设备写接口会被拒绝。
3. 管理员或运维人员能新增、编辑、启用/停用设备，重新读取后数据仍存在。
4. 指标页能展示四项内置指标及各自单位和范围。
5. 本地数据库包含用户、设备、指标和遥测事件四张基础表。
6. 项目提供遥测 JSON Schema 示例，且本迭代不提供数据模拟、接入或告警页面。
